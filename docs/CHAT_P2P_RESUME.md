# Chat P2P file resume

Chat direct transfers support files and original videos from 1 byte through
5 GiB (5,368,709,120 bytes). Both participants must use the updated client.

## Deployment

Apply `supabase/migrations/202609280074_chat_transfer_resume.sql` after the
existing chat migrations. This adds `chat_transfer_v2`; the client reports a
configuration error if it is missing. No Storage bucket is created.

## Resume flow

- Choose the existing direct-transfer action in a chat to send a file/video.
- A disconnect, background suspension or leaving the transfer page retains
  progress. The sender can reopen "Unfinished file transfers" in chat and
  resume the same task. The recipient must accept the renewed offer.
- The original sending device ID and file reference are stored in the local
  account-scoped chat cache. Android uses persisted document URI access.
- The receiver flushes file data and checkpoints each 1 MiB. On resuming it
  discards any unacknowledged tail and reports the retained byte offset.
- Both ends rehash the retained prefix locally. Only remaining file bytes
  traverse the DataChannel. Completion requires matching whole-file SHA-256.
- Explicit cancellation or checksum failure discards the receiver's partial
  file. A checksum failure requires a new transfer, rather than trusting the
  retained bytes. Accepted/reoffered tasks expire after seven days.

Supabase handles authentication, metadata and SDP/ICE signalling only. File
bytes never fall back to Storage or a cloud drive. The existing STUN-only
connection policy remains; networks that prevent direct connections can still
fail. This change does not add a TURN relay or guarantee background execution.

## Validation

`test/direct_transfer_test.dart` covers simulated interrupted sessions reopened
from persisted checkpoints, exact remaining byte counts, unverified tail
truncation, whole-file corruption rejection and cancellation.

`supabase/tests/chat_transfer_resume_test.mjs` runs the actual migrations in
PGlite, covering the 5 GiB boundary, restart/signalling reset, reacceptance,
account/device/privacy/block restrictions and completion recovery. Set
`PGLITE_MODULE` to a PGlite module URL, or use the local cache path documented
in that test. Physical Android/Windows multi-gigabyte and cross-network tests
are still required before release. No APK is generated by these checks.
