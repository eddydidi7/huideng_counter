# 笔记阅读与超长正文升级（2026-09-20）

## 本次变更

- 语速范围 0.3–3.0，每步 0.1；按账号保存本地阅读偏好。默认仅首次使用为 1.0。
- Android `ReadingService` 独立持有离线系统 TTS、媒体会话及前台播放通知。Home、普通返回、Activity 暂停与 Flutter 页面销毁不主动停止朗读；暂停、停止与“完全退出阅读 / 停止朗读”是显式操作。音频焦点被电话等占用时暂停。
- 通知提供上一段、暂停/继续、下一段、停止；只选择不要求网络的已安装语音。没有语音包时显示提示与系统安装入口。
- Flutter 返回阅读页后读取原生会话快照。原生每约 3 秒保存位置，段落结束/控制操作立即保存；进程被终止后不自动播放，用户可继续。
- 长正文以最多约 2048 字符的阅读块延迟创建可见控件；编辑器以约 16000 字符分块加载，提供前后块切换和全文搜索。大段粘贴会重新分块。
- 只在正文实际改变后启动延迟保存；普通笔记约 1.2 秒、分块编辑约 1.8 秒。大正文解析、组合与序列化放在后台 isolate。保留原有正文格式与版本冲突保护，不删除旧笔记或历史。
- SQLite 分段读取长 TEXT，列表只读取摘要，避免 Android CursorWindow 单行大小限制。不依赖 Android 8 可能缺少的 JSON1 扩展。
- 顶栏使用淡蓝色“阅读模式”，淡蓝色放大竖三点菜单，保留“完成”。分享入口在更多菜单中。

## 数据库部署

执行 `supabase/migrations/202609200043_long_notes.sql`，不要重新运行旧建表脚本。

本脚本新增：

- `note_transfer_parts`：账号隔离的上传暂存块及校验值。
- `note_transfer_results`：已提交请求的分块响应，支持重复请求。
- `note_committed_versions`：云端已提交旧版本。
- `note_transfer_v2`、`pull_note_heads_v2`、`pull_note_part_v2`：长正文传输。
- `note_text_characters`、`archive_note_version`：长度校验和保留旧版本。

调整既有 `sync_note_v1` 长度校验，保留身份验证、作者隔离、版本比较、冲突副本和请求幂等机制；不重建已有表、不删除正文或版本。完成上传后会清空该次临时分块的重复内容，保留校验值；此操作不清空笔记。迁移已在本地 PostgreSQL 兼容测试环境中连续执行两次。

单篇文本限制 5,000,000 Unicode 字符；富文本数据请求上限 64 MB（含嵌入图片、JSON 格式等），不是无限图片容量。网络以约 128K 字符一块传输；失败保留本地正文与原请求，重试不创建重复笔记。长笔记不反复上传全部本地历史，云端保留每个已提交旧版本。

无需替换 `admin-api` 或其他 Edge Function。本轮尚未执行线上迁移，也未构建新 APK；原生服务和客户端改动需随下一版 APK 安装后才能使用。
