# 用户资源用量管理（049）

## 部署顺序
1. 已执行 047 后，若尚未执行 048，请先执行 `202609200048_public_resources_large_files.sql`。
2. 执行 `supabase/migrations/202609200049_resource_governance.sql`。该脚本增加记账表、限制、RPC 和触发器，不删除现有用户文件。不要在 049 后再次执行旧版 047/048，以免覆盖新的上传校验。
3. 更新 `admin-api`：使用 `outputs/huideng_admin/supabase/dashboard-admin-api.ts` 完整替换 Dashboard index.ts。
4. 更新 `public-resources`：使用 `docs/deployment/public-resources-dashboard.ts`。若使用个人 OSS 文件服务，也更新 `docs/deployment/storage-token-dashboard.ts`。
5. 更新 Windows 后台程序和 Android 客户端。新客户端依赖 049 的上传检查 RPC，须先部署数据库。此轮未生成安装包，未替用户执行线上部署。
6. Supabase 全局 Storage 单文件限制仍须满足大文件需求，例如设为 1 GB；桶限制和客户端限制仍分别生效。

## 功能与数据口径
- 后台“用户资源用量”可搜索、分页、服务端排序和筛选，查看类型占用、上传字节和文件数、配额、警告、限制、封禁状态。
- 统计现有 counter-images、chat-avatars、forum-files、chat-files、chat-voice、group-files、public-resources，以及个人云盘 user_files 元数据。无法归属用户的对象单独提示，不能冒算到其他账号。
- 文件详情只含名称、类型、大小、来源、时间；不提供私人笔记、私人聊天正文或附件预览链接。
- 红书与论坛使用同一帖子表，合并计数；结缘单独计数。来源通过附件元数据识别。类型基于扩展名/MIME，不是文件内容检测或病毒扫描。
- 升级前只能根据仍存在的文件回溯上传历史，无法恢复已删除文件或历史覆盖上传；升级后的上传事件保留。日/月边界使用北京时间。
- 实际下载流量显示“暂无法精确统计”，不提供虚假的下载流量排序。公共网盘“下载签发量”单列，不能当作实际下载字节或账单。
- 默认个人总配额 1 GiB、每日上传 1 GiB/100 个、每月 10 GiB/2000 个；可逐用户修改。总配额包含在传文件预留，公共网盘全局额度也继续生效。

## 服务端约束
- 管理 API 校验当前账号及管理员角色，RPC 再次验证；列表排序筛选在服务端执行。变更带版本检查、审计及请求幂等保护。
- 上传前 RPC、元数据预留触发器及 Storage 对象完成写入触发器共同检查配额、上传次数、类型、暂停期限和封禁状态。同一用户通过事务锁串行记账。
- 降低配额、超额或封禁不会删除已有文件，只阻止新的上传。已开始传输的数据可能仍消耗临时存储或流量，不能将配额功能视为云厂商账单硬上限。
- 普通文件限制包括文档/APK/视频/音频等非图片。支持暂停全部上传及临时类型限制，期限到达后自动失效。
- 下架公开帖子/资料只修改公开状态；公共资料不能由上传者重试上传自动恢复公开。
- 警告在联网客户端打开及周期检查时显示（约 1 分钟）；不是系统推送，也不代表用户已读。
