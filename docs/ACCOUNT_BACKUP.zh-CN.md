# 注册、密码与本地备份

## 当前状态

已增加 APP 入口和实现，尚未替用户注册真实账号、发送邮件或验证真实收信。当前测试项目此前未配置 SMTP；用户本次注册的具体报错尚待提供，不能将 SMTP 当作已经证实的唯一原因。

## 邮件服务必须先配置

Supabase 默认邮件服务只向项目团队邮箱发信，且默认限额为每小时两封。普通用户注册、重发确认和找回密码需管理员配置 SMTP 或 Send Email Hook。参考 [官方 SMTP 文档](https://supabase.com/docs/guides/auth/auth-smtp) 和 [限额说明](https://supabase.com/docs/guides/auth/rate-limits)。不在 APP 放任何邮件密钥，不通过关闭邮箱确认绕过限制。

在 Authentication → Email Templates 中分别更新：

- Confirm signup：使用 `supabase/templates/confirm_signup.html`。
- Reset password：使用 `supabase/templates/reset_password.html`。

两份模板使用官方支持的 `{{ .Token }}` 显示验证码。尚未把模板部署到云端。默认模板只带链接，必须替换后才能按 APP 的验证码流程完成确认和重置。参考 [邮件模板](https://supabase.com/docs/guides/auth/auth-email-templates)。

## APP 操作

1. 注册：填写有效邮箱及至少 8 位密码；收到邮件后进入“确认邮箱／重发邮件”填写验证码，再返回登录。
2. 修改密码：登录后从“我的 → 修改密码”输入当前密码和两次新密码。独立 Auth 会话验证原密码后调用 updateUser，并提供 currentPassword。
3. 忘记密码：填写邮箱、申请邮件、输入验证码及两次新密码。采用 recovery 类型验证后更新密码。无需跳转网站、深链接或额外域名。
4. 确认／恢复会话不切换主 APP 当前账号，不把访客记录自动归入邮箱对应账号，也不把验证码或密码写入本地备份。

正式上线前实测：错误原密码、弱密码、过期验证码、请求限流、错误邮箱、重发、重置后的旧密码拒绝及新密码登录。发信请求返回成功时使用条件性提示，不据此向第三人确认邮箱是否存在。

## 本地备份

“我的 → 本地备份与恢复”导出 `.huideng` 文件，包含当前账号或访客的项目、项目顺序、已下载图片、语言等设置、会话、逐次计数和人工校正历史、事件 UUID 与设备来源。不导出密码、登录 token 或同步游标。

- 文件未加密，保存到私人位置；SHA-256 用于检测损坏，不是防伪签名。
- 当前整包上限 100 MB、单张图片 20 MB；更大备份需要后续流式归档方案。
- 本地图片缺失时明确报错，避免把不完整备份报告为成功。
- 导入只允许同一账号；访客备份在访客模式导入，之后可使用原“导入访客记录”流程认领。原认领标记保留。
- 导入先自动保存本地恢复备份，再在独立临时 SQLite 中校验表结构、外键、字段、校验和、事件归属及图片。正式合并使用单个事务，相同事件 UUID 内容冲突即回滚。
- 已有项目名称、图片、顺序和既有会话资料保留，只添加缺失记录；语言等设置可勾选恢复。不会用备份的最终总数覆盖当前累计值，累计值由事件并集重新求和。
- 暂停当前同步工作器后导入，新事件重新排队但保留原 UUID、设备来源和已冻结上传内容。不会导入旧同步游标或把新记录误标为已上传。在线同账号恢复后的云端资料可能提示既有版本冲突，按现有冲突界面处理。
- SQLite 用户库结构未变，未清空现有数据。文件选择和权限、手机大文件、真实云端恢复还需安装新版后验收。

## CSV 导出
主要导出按钮为 CSV，UTF-8 BOM 编码，支持 Excel/WPS。包含项目及逐次计数历史、操作来源、备注和 UUID。CSV 用于查看和分析，不含图片和设置，不能直接导入恢复。完整恢复请使用保留的 .huideng 备份功能，旧备份仍可导入。
