## 按顺序部署

1. Supabase SQL Editor 执行 `supabase/migrations/202609200047_public_resources.sql`。新增配置、文件元数据、下载签发记录三张表及服务端 RPC；创建私有 `public-resources` bucket。不删除现有用户文件。
2. Edge Functions 新建或更新名称为 **public-resources** 的函数。把 `docs/deployment/public-resources-dashboard.ts` 整份粘贴到 index.ts 并部署（不要只复制模块入口文件）。
3. 该函数关闭 **Verify JWT with legacy secret** 并保存。POST 在函数内验证登录身份；PUT 使用限时 HMAC 上传凭证，并再次检查账号、上传开关、大小和校验值。不能移除这些内部检查。
4. 更新 admin-api：使用兄弟项目 `huideng_admin/supabase/dashboard-admin-api.ts` 整份单文件代码。无需额外填写存储密钥，函数使用 Supabase 注入的服务端环境变量。
5. 使用包含本次修改的 Windows 后台，进入“公共网盘”。超级管理员可保存设置，管理员可查看及删除文件。旧版 Windows 程序不会自动增加这个页面，需要更新程序。
6. 使用包含公共网盘 v1 接口的客户端实测：甲上传小文件→乙刷新后下载→比较内容；关闭上传后上传应失败但下载仍成功；管理员删除后不再显示。部署成功不等于该跨设备验收已通过。

本轮不构建 APK。首次增加客户端界面需要更新客户端；已支持 v1 的客户端可沿用该接口，后续开关和限额由服务端生效。

## 默认设置

- 总开关、用户上传、用户下载均开启；正式登录用户可使用，访客需注册。
- 文件大小与 SHA-256 校验成功后立即公开，没有人工审核队列。
- 全体共享容量上限 1 GiB，单文件默认 20 MiB（后台最多 50 MiB）。这些是应用限额，并非购买的云容量；仍受实际 Supabase 套餐、存储桶限制、Edge 运行限制及账单约束。
- 每人每日上传额度 100 MiB、下载链接签发额度 500 MiB；每日最多 100 次新上传、最多 10 个待完成上传。每日按数据库时区切日。
- 普通用户不能删除；后台删除有确认框和审计记录。
- 分类、公告、容量和每日额度均可后台配置。关闭上传不会自动关闭下载。

## 实现和限制

上传通过 Edge 接收原始文件，校验长度与 SHA-256 后写入私有对象存储；数据库只保存元数据。保留原文件名及扩展名，APK 使用正确 MIME。文件超过 50 MiB（包括较大的 APK）本版会拒绝，尚未实现大文件分片或断点续传。

失败保留客户端本地任务，可重试；服务端上传租约最长 5 分钟，网络结果不明确时需稍后重试，避免覆盖或并发删除。管理员删除正在上传的文件会先隐藏，租约结束后再次刷新后台继续清理；不是自动定时清理服务。对象删除成功后才释放已占用容量。

下载链接有效期 120 秒。关闭下载阻止新签发，已签发链接最多约 2 分钟仍可用。签发额度是按链接记录的应用限制，不是运营商流量硬封顶，同一有效链接可能被重复使用。应结合 Supabase 用量/账单监控控制实际费用。

私有存储桶仅供服务端访问，不应另加允许普通用户列出、覆盖或删除该桶文件的 Storage 策略。已有同名公开桶时 SQL 会中止，需先核实桶用途，不自动修改旧桶权限。
