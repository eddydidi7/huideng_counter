# APK 分享与 Android 系统安装

## 本次实现
- 私聊、群聊原有文件选择器支持 APK；文件名、.apk 后缀、MIME 保留。
- 聊天 APK 上限500MiB，先复制到应用专用目录再进入现有离线发送队列；失败暂停自动重试，手动点击重试。原文件不删除。
- 流式上传/下载、进度、下载长度检查；有服务端SHA256的群文件/资料校验摘要。下载完成才将.part重命名为.apk。
- APK卡片显示Android安装包、名称、大小、下载/安装；资料显示时间，Android下载后可读取版本。
- Android使用独立FileProvider，只共享files/apk_share目录，content:// URI和只读临时权限。
- REQUEST_INSTALL_PACKAGES；未授权时打开本应用的系统“安装未知应用”设置，返回获准后打开系统安装确认。
- 安装前来源提示，用户最终在系统中确认。没有静默安装、权限绕过、自动点确认。
- 群长期文件支持500MiB APK并保留.apk存储后缀；原文档仍100MiB。保留成员、审核及群文件权限。
- Windows保存文件；iOS仅系统分享/保存，不显示安装。iOS原生代码尚未在Xcode编译。
- 已有在线直传接收文件的APK打开也进入同一安全入口。

## 部署和实际限制
1. 在SQL Editor执行supabase/migrations/202609200042_apk_sharing.sql。脚本不删除用户记录或文件；调整两个大小约束和两个桶的上限，增加attachment_mime_type并沿用现有权限。可重复执行。
2. 必须在下一次生成的新APK中安装客户端能力；当前手机旧版本不会自动拥有安装入口。
3. 500MiB是应用/桶配置上限，不代表云项目已能接收500MiB。Supabase Free全局单文件最大50MB；付费项目仍需按实际计划配置全局限制。没有自动升级套餐。
4. 公共网盘public-resources仍是未启用的占位服务；资料页APK入口已就绪，但真实上传下载需要先选定存储并实现/部署v1后端。没有把私人网盘公开，也没有开启收费服务。
5. applicationId保持org.huideng.huideng_counter，现有release签名配置未改；覆盖更新仍要求接收的APK同包名、同证书、版本号合适。系统负责校验。任意第三方APK不保证可安装。

## 真机验收（下一次更新APK后）
- 两个账户：聊天发送小于实际云限额的APK，接收方进度到100%，点击安装先出现来源提示。
- 关闭安装来源权限，点继续进入系统设置；拒绝时不安装，允许后返回显示系统确认；取消不改变手机。
- 再次打开文件复用缓存；断网下载不能出现可安装的残缺文件，恢复网络可重试。
- 同包名同签名更高版本进入系统更新确认；签名不同由Android拒绝。
- 群文件列表测试已加入/退出/新成员的历史权限。
- 资料库启用后再测试上传下载，不能把占位接口当作已开通。
