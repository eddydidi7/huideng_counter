# 内容互通与群学习功能（2026-09-18）

## 状态与发布边界

本轮修改了客户端代码、准备了 030/031 数据库迁移、shared-page Edge Function 和独立公开网页服务。没有连接线上执行迁移、部署函数或网站；没有生成 APK，没有删除现有用户文件。030/031 尚待用户执行。

同一个 Supabase Auth 用户 ID 继续关联所有模块。新页面不注册第二套账号；本地笔记/计数沿用按账号隔离的 SQLite 数据库。当前聊天页的顶栏、输入栏、附件宫格和消息排列未重写；新增长按菜单、群信息入口、分享卡片与头像跳转。

## 新增数据库表

030：
- shared_pages：指向红书已发布内容的分享记录，随机 slug、有效期、撤销时间；不复制私人笔记数据库。
- community_profiles：简介、是否公开个人号。
- community_config：公开网页入口 public_base_url、下载链接 download_url；可由 Supabase Table Editor 管理。

031：
- chat_group_settings：禁言、上传、历史文件访问、群容量。
- chat_group_roles：管理员/成员、个人禁言截止时间。
- chat_group_folders：群文件夹和顺序。
- group_file_reservations：上传容量预留。
- community_files：文件提供商、对象键、文件名、大小、校验值。
- chat_group_files：群、上传者、文件引用、文件夹、相册、时间。
- chat_group_content：公告、精华、活动。
- chat_group_reads：成员已读回执。
- group_practices：群共修目标。
- group_practice_members：参加记录。
- group_practice_counts：按用户/计数事件去重的贡献。
- saved_content：私人收藏的资料引用。

已有表字段：
- app_notices：group_id；后台 Table Editor 为共修通知填写现有群 UUID，详情显示“进入共修群/参与群共修”，实际群内容仍要求成员权限。
- forum_posts：access_level、post_kind、rich_body、source_note_id。
- 本地 notes：source_post_id、source_meta；沿用云端 user_notes.data JSON 同步，无需暴露 notes 表。
- 本地 SQLite 版本7新增 practice_links、practice_outbox，升级前保留现有备份机制。

## 权限与存储说明

- 新表默认 RLS，不把原始私人记录授权给公开角色。RPC 按 auth.uid()、是否群成员和群角色校验。
- link_only 从公开流、搜索、个人主页隐藏。分享令牌64位随机十六进制，可撤销/换新/过期。转发令牌的人相当于转发阅读权限。
- 私密、下架、过期、撤销后不能继续取得新的网页正文/签名。已经下载的副本无法远程收回，已签名媒体 URL 最多仍有短暂有效期。
- 访客不可上传、下载群文件；注册账号后仍须具备群成员权限。
- 群文件默认每文件100MiB、每群1GiB的代码限额，不代表免费额度；实际存储和流量由 Supabase 方案计费。平台管理员可在 chat_group_settings.storage_limit 调整字节数；普通群管理员不能自己提高配额。
- 上传先预留容量，storage.objects 策略校验预留大小，完成时再次核对服务器对象大小。未完成预留也计入配额，避免失败任务绕过限制。
- App中的“移除群文件”是撤销群内访问，提示实体仍保留；实际清理孤立对象和释放容量需平台管理员处理，不能把它误称为已回收存储费用。
- 群共修是用户自报计数，不是防伪证明。离线补交要求账号仍有群权限；App关闭时不保证后台持续运行。
- 现有聊天附件传输流程保留；本轮统一适配器用于红书与群文件，尚未把每个旧上传模块都迁移到同一实现。
- 公共网址配置保存在后台，但首次使用这些新能力仍需要包含本轮代码的新客户端。

## 部署顺序（开发记录，不要求用户一次操作完）

1. 在 Supabase SQL Editor 执行 030_content_sharing；反馈成功后再指导下一步。
2. 执行 031_group_learning。
3. 部署 shared-page Edge Function，verify_jwt=false（以64位分享令牌授权公开读取）；只用 Supabase 默认服务端密钥，不向客户端放 service_role。
4. 部署 outputs/huideng_public_web，参见该目录 README；配置实际独立域名和下载地址，再把网址填入 community_config。
5. 用户明确要求生成 APK 后才构建。随后在两台真机核对跨账号私密隔离、分享、群上传和计数补交。
