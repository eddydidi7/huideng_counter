# 笔记快捷菜单实施状态

整体状态：部分完成，不能视为本次全部要求已经交付。

## 已接入源码

- 长按弹出紧凑的图标文字菜单；选中多篇后长按仍可调整选择。
- 置顶、收藏、归档、快速访问按单篇当前状态显示对应操作。
- “选择笔记”进入原有多选模式；保留批量置顶、收藏、归档和回收站。
- 快速访问独立保存在原有 source_meta 中，复用既有账号同步。
- 复用原分类体系，允许一篇笔记加入多个已有笔记本；添加和移动分开。
- 分类重命名和删除保留其他分类关系、正文及原有状态。
- “分享到…”二级菜单复用红书编辑草稿、现有单会话聊天、复制文字、
  Android 系统文字分享、TXT/Markdown/PDF 导出。
- 复制链接只查询已有公开文章链接，不自动生成公开快照；私人笔记没有
  已公开链接时不会被公开，也不会生成伪造的可访问链接。
- Windows 尚无系统分享桥接：明确提示并提供导出，不声称已系统分享。

## 尚未完成

- 正文实体、内容哈希、用户引用、写时复制、跨模块附件统一引用。
- 基于写时复制的“创建副本”；没有用全量复制冒充该功能。
- 完整共享文章系统、发布元数据、评论开关、更新、撤销、批量分享。
- 主动发布到个人主页文章，并与统一内容实体及权限结合。
- 朋友、群和最近聊天的混合多选与引用发送；现有入口仍是单会话草稿。
- 私人笔记定位链接及服务端访问授权，区别于现有公开文章快照链接。
- 引用安全的永久删除；回收站目前仅复用恢复，不新增危险实体清理。
- Windows 原生系统分享、长文章的系统文件分享。
- 所有既有图片和附件的跨目标去重保证；现有红书分享只复用原编辑入口，
  不应据此宣称全部附件迁移和正文去重已经实现。

## 需要保持的边界

现有 PublishedNotesPage 是配置下发的资料列表；note_web_link_v1 是明确
发布后才存在的公开快照。这两者都不是本次要求的完整共享文章实体系统。
不可将它们重新包装为“已经具备共享文章系统”。

实现后续服务端内容引用时，必须同时审查旧版正文同步、历史版本、备份、
账号切换、附件权限、删除及垃圾回收，不能只在 Flutter 隐藏发布按钮。
没有运行生产迁移、公开私人笔记、自动批量迁移旧内容或生成安装包。
