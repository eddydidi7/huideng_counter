# 聊天首页：文件传输助手整合需求

记录日期：2026-09-28

状态：待实施。本文件仅记录新需求，不代表相关功能已实现或验证。

## 首页结构

1. 取消顶部固定的“未完成的文件直传”区域。
2. 取消顶部固定的“文件传输助手”入口。
3. 两者合并为一个“文件传输助手”会话，与群聊、好友私聊混排在同一个聊天会话列表中。
4. 首页结构为：搜索/功能顶栏、统一聊天会话列表。不得再为直传任务另占固定区域。
5. 所有会话统一按照最近活动时间排序；文件传输助手不固定置顶，无新活动时自然排到下面。

## 会话行

- 名称统一为“文件传输助手”。
- 可以使用固定的文件传输助手图标，与普通用户头像区分。
- 列表尺寸、行高、文字布局与普通聊天会话一致。
- 未完成任务直接显示在该会话的摘要中，例如“佛学资料.zip · 传输中 63%”或“2个文件等待继续传输”。
- 点击会话进入统一的文件传输管理页面，不再分成两个入口。

## 管理范围与活动时间

- 统一管理正在传输、暂停、继续、失败重试、断点续传及已完成记录。
- 新文件传输、恢复传输和完成传输时，更新会话最后活动时间，使其自然参与列表排序。
- 活动时间应反映真实传输事件；仅打开页面、刷新列表或重启应用，不应人为将其置顶。
- 合并入口不应丢失已有未完成任务、续传状态或已完成记录。

## 文件本体硬性限制

- 文件本体继续采用 P2P 直传，不进入 Supabase Storage，不上传公共网盘或个人云盘，不消耗 Supabase 文件 Storage/Egress。
- Supabase 如有需要，只能保存很小的信令或状态数据，不能保存大文件本体。
- P2P 失败不得静默回退为 Supabase Storage 或云盘上传。

## 验收要点

1. 首页顶部两个旧入口均消失，列表中仅有一个统一的文件传输助手会话。
2. 例如群聊 18:02、文件传输助手 17:55、好友私聊 12:38 时，按上述顺序展示。
3. 新传输、恢复和完成后，时间及排序同步更新；无新活动时不固定在前面。
4. 单任务进度或多任务待续传摘要直接体现在会话行中。
5. 从该会话可访问各类任务、执行暂停/继续/重试，并查看完成记录。
6. 合并前后的文件本体传输路径均满足 P2P 限制，失败也不上传云端文件存储。

## 后续实施核查

实施时需核查现有会话数据源、任务记录、最后活动时间持久化和排序机制，复用普通会话的行布局。空任务状态、跨设备记录范围等细节需依据现有架构确定，不在本次需求记录中宣称已经支持。
