# 笔记阅读模式切换修复

日期：2026-09-28，版本：1.0.68+69。

## 代码中发现的原因

- 普通笔记和长文编辑器原来使用 Navigator.push，不是销毁编辑器再打开阅读页；这条路径也没有 WebView。
- 阅读页原来先创建默认深色加载界面，再解析正文、读取阅读主题和位置，且等待语音列表/会话查询后才显示正文。
- 正文显示后通过 post-frame 回调恢复阅读位置，并调用 immersiveSticky 改变系统栏，造成额外布局变化。
- 退出及 dispose 都恢复系统栏并调用原生 exit，存在重复处理。
- 编辑器没有传递可见文字位置，阅读器仅恢复自身保存的位置。

## 本次处理

- 两个编辑器共用 openNoteReader：保留已挂载的编辑器，用内存正文准备段落及偏好，准备完成后才切换路由，不添加延时或 Loading 遮罩。
- 模式路由不使用推入/退出动画；首帧同步使用准备好的正文和最终阅读主题。
- 语音初始化不再阻塞正文显示。保留 TTS 会话恢复、播放控制和进度联动。
- 通过 Quill 的可见文字坐标得到文档偏移；长文额外累计前面分段的长度。不会使用停留在文章开头的旧光标位置代替阅读位置。
- 首次滚动恢复在视口布局阶段完成，使用已布局段落的文字位置修正滚动偏移，并在同一帧重排，避免下一帧才跳转。长单段同样定位到段内文字。
- 模式切换保持系统栏布局不变，取消反复进入/退出 immersive 模式；退出原生清理只执行一次。
- 原编辑器继续保留控制器、正文和滚动状态；不改写笔记内容。阅读位置记忆、双击控制栏、设置及进度条继续保留。

## 验证

- 18 项定向 Flutter 测试通过，覆盖首帧主题/正文、TTS 等待期间显示、真实 Quill 可见文字位置、长单段首帧定位、返回页面与滚动状态、原生退出次数、长文分页、进度拖动、Windows TTS、笔记自动保存及控制栏。
- 未进行 Android/Windows 真机录屏验证；系统合成器、显示驱动或设备特有闪屏仍需真机确认。
- 未生成 APK 或其他安装包。
