> # 慧灯计数器 —— 聊天、通讯录、群文件、共享文件、网盘、断点续传 总开发要求
>
> 请基于当前 Flutter 项目增量开发，不要推翻现有架构。
>
> 统一原则：
>
> * 使用同一个 Supabase Auth 账号
> * 不再建立第二套聊天账号
> * 所有私人数据按 `auth.uid()` 隔离
> * 文件与数据库分开存储
> * 大文件避免全部压在 Supabase Storage
> * 所有传输优先支持断点续传
>
> ---

> # 三十、断点续传核心要求
>
> 遇到以下情况：
>
> * 网络断开
> * Wi-Fi切换移动网络
> * App进后台
> * App被关闭
> * 手机重启
> * 对方掉线
> * 服务器临时失败
>
> 恢复后：
>
> **必须从已完成位置继续**
>
> 不能从0重新传。
>
> ---
>
> # 三十一、分块传输
>
> 大文件采用：
>
> **Chunked Upload / 分块上传**
>
> 建议默认：
>
> * 4MB
>   或
> * 8MB
>
> 不要一次把整个文件读入内存。

> # 三十七、完整性校验
>
> 文件完成后使用：
>
> **SHA-256**
>
> 校验。
>
> 如果某些分块损坏：
>
> 只补传损坏的块。
>
> 不要整个文件重新传。
>
> ---

> # 三十八、下载也支持断点续传
>

>
> 完成后：
>
> * SHA-256校验
> * 原子重命名为最终文件
>
> 防止半文件被误认为完整文件。
>
> ---
>
> # 三十九、P2P 也要支持断点续传
>
> WebRTC 大文件传输：

> * 断线重连后只补发缺失块
>
